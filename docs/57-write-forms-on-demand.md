# docs/57：写表单不常驻 —— 按需的「添加」与「编辑」

用户第 324 轮原话（逐字，附 `/network` 订阅区块的截图）：

> 这个界面不要常驻，应该点击添加才会有，或者说点击编辑编辑

那一屏原来把「新建 / 覆盖订阅」整张表单（11 个字段）**常驻**在列表下方，
把只读的订阅表挤成半屏，而它绝大多数时间用不到。这一轮把它改成**按需出现**：

```
区块工具栏：  [添加订阅]  ← 表单的入口（空列表上也在，否则第一条永远建不出来）
每行操作列：  [编辑] [刷新] [删除]   ← 第 324 轮新增；点开的是**预填**的同一个对话框
```

线路区块（同一页、同一个毛病）用**同一套改法**，理由见 §1。

---

## 1. 为什么线路也要一起改

用户截图只指了订阅那一段，但 `/network` 上「订阅」与「线路」是**并排的两个区块**，
写表单都是常驻的。只改一个会留下一页之内两套规矩 —— 那比"都常驻"更难解释。
所以这一轮两边一起改，改动面也是对称的。

---

## 2. 这一轮真正难的地方：**「编辑」有两条会静默写坏的路**

把表单藏起来、加两个按钮，是十分钟的事。难的是"编辑"这件事本身 ——
仓库里有两条既成事实，各自都能让"编辑"变成**保存成功、数据已坏**：

### 2.1 订阅地址是**遮蔽**的 —— 回填就等于把 `***` 存进配置

`SubscriptionRow.url` 是 `maskSubscriptionUrl()` 处理过的
（`src/pages/network/model.ts`，文件头明写"**原始地址没有任何进入 DOM 的路径**"）。
它是唯一出口，因为在设置页/日志/截图里泄露订阅 token 等于泄露账号。

于是「编辑」面对一个矛盾：

* 地址框**不能**回填遮蔽值 —— 用户点一下保存，`...?token=REAL` 就变成了
  `...?token=***`；那一刻不报错、还显示"已保存"，**下次刷新才全挂**；
* 地址框也**不能**显示明文 —— 那正是上面那条规矩要防的。

**解法**：编辑时地址框**留空**，语义是 **「留空 = 不改地址」**，
由后端保证（§3）。提示语照实说：

> 当前的地址已保存在配置里、这里不回显（它带密钥）。留空 = 不改地址；只有填了新地址才会替换。

遮蔽后的现值只作为**占位符**给出 —— 用户看得见"当前有这么个地址"，但没被填进输入框。

这与服务商密钥已有的口径**逐字相同**（`providers.edit.keyHint`：
"留空 = 不改已保存的密钥；只有填了新值才会写进密钥仓库"）。不是新发明的约定。

### 2.2 `upsert` 是**整条覆盖写** —— 不回带底稿会清空 `disabled_nodes`

`subscription_upsert` 在 Rust 里是 `*slot = subscription.clone()`（整条替换），
而表单里**没有也不该有**这些字段：

| 字段 | 谁在写它 | 不回带的后果 |
|---|---|---|
| `disabled_nodes` | [docs/54] 订阅详情页的逐节点开关 | **用户关掉的节点全部被重新打开** |
| `user_agent` | 无界面入口 | 被打回 `clash-verge/v2.0.0` |
| `provider_key` / `extra` | 派生 / 历史键 | 被重置或丢失 |

`disabled_nodes` 那条最要命：它是用户**逐条点出来**的偏好（那些"剩余流量：…"之类的
信息节点就是靠它排除的），而清空它**不会报任何错**。

**解法**：归一化时留一份**回带底稿** `base`（`model.ts`），编辑载荷以它为底、
只覆盖表单真正管的键 —— 与 [docs/23] 为 `provider_upsert` 定的纪律逐字相同
（"以原始记录为底，只覆盖用户真的改过的那一个键"，见 `pages/providers/editor.ts`）。

两处细节都不是随手写的：

* **底稿取的是实体，不是 `SubscriptionView` 本身**。视图还带着
  `node_count` / `group_count` / `parser` / `error` / `userinfo` —— 把它们发回去会被
  Rust 的 `#[serde(flatten)] extra` 收下、**写进配置**（配置里凭空多出运行时字段）。
  所以 `base = { ...inner }`，并且**剔除 `url`**（唯一不能进 DOM 的字段）。
* **空的可选字段必须显式删键**。新建时"留空就不发"是安全的（没有旧值可留）；
  编辑时那样做会让**底稿里的旧值活下来** —— 用户明明清空了排除正则，保存后它还在。
  所以 `laneEditPayload` 先把四个可选键全删掉，再按草稿填。

## 3. 后端：`subscription_upsert` 的「留空 = 不改地址」

`src-tauri/src/commands/net.rs`：

```rust
match doc.proxy_subscriptions.iter_mut().find(|x| x.id == subscription.id) {
    Some(slot) => {
        if subscription.url.trim().is_empty() {
            subscription.url = slot.url.clone();
        }
        *slot = subscription.clone();
    }
    None => doc.proxy_subscriptions.push(subscription.clone()),
}
```

**只对已存在的条目生效**：新建时留空仍然照常被校验器拒（`TA-5001`），
那条由既有的 `subscription_upsert_refuses_invalid_and_writes_nothing` 守着。

返回值是**真正存下去的那条**（含原地址），所以前端结果区显示的仍是后端真值 ——
不是前端拼的一句"保存成功"。

## 4. 表单进对话框：三条取舍

1. **对话框，不是"就地展开"**。仓库里"新增/编辑一个实体"的既有形态就是对话框
   （`ProviderAddDialog` / `PricingDialog` / 服务商向导），而且用户的原话是
   "点击添加**才会有**"—— 对话框与这句话最贴。
2. **主操作放在 `DialogActions`**（[docs/28 §1.7]）：长表单滚到底也看得见「保存订阅」，
   「关闭」永远在，不逼用户去点遮罩。
3. **按需挂载，不是 `open` 开关**。父组件在关着时直接 `null` ——
   **草稿状态随卸载一起消失**。否则"换一行编辑"会把上一行的输入带过来，
   那是个会**静默改错实体**的坑（A 的名字被存进 B）。
4. **id 在编辑时锁死**：`upsert` 按 id 命中，改 id 等于换一条实体。
   想换 id 就新建一条，别让"编辑"静默改名。

### 新增的 4 条（`㉑ [docs/57] …` 一组）

1. **表单不常驻**：打开页面时两个写表单的容器、字段、提交按钮**一个都不在 DOM 里**；
   点「添加」出现、点「关闭」消失；两个区块都验（不能只改一个）。
   这一条是"不常驻"的**可执行判据**，不是靠"看起来短了"。
2. **「编辑」回填 + 地址留空**：非秘密字段如实回填（名称/正则/周期/健康检查地址），
   **地址框是空的**、且**绝不含 `***`**，遮蔽值只出现在 `placeholder` 里；id 被 `disabled`。
3. **编辑保存不写坏**：载荷里 `url` 是空串（交给后端保持原值）、
   **整个载荷的 JSON 不含 `***`**；`disabled_nodes` / `user_agent` / `provider_key` /
   `health_check` **原样回带**；且**不许混进** `node_count` 等视图字段。
4. **线路编辑清空可选项真的清掉**：把 `exclude_filter` 清空后，载荷里**没有这个键**
   （而不是让底稿里的旧正则活下来），同时没动的 `filter` 照旧。

## 6. 本轮**没有**做的事

* **没有**改任何命令的签名或数量 —— 契约条数不变（仍是 116），没有新命令。
* **没有**让地址可回显：遮蔽那条规矩原样保留，编辑走"留空 = 不改"。
* **没有**动 `/network/nodes` 与 `/network/subscriptions/:id`（[docs/54] 加的订阅详情页）
  —— 它们本来就只在点进去时出现。
* **没有**给"编辑"做乐观更新：仍然是"后端真值回来 → invalidate → 列表重取"，
  结果区显示的仍是 `subscription_upsert` 的返回值。

## 7. 我自己犯的错（如实）

写这一轮的测试时，有三次是**测试先红、证明我写错了**，而不是产品坏了 —— 记下来：

1. 把对话框的 `data-testid="network-*-write"` 留在**内容 `Stack`** 上，
   而问号圆圈（HelpTip）在 `DialogTitle` 里 —— 于是"这个表单里只有一个问号"
   那条断言在容器里找不到任何问号。改成把 testid 挂在**对话框**上，
   "写表单"的容器语义才对（标题 + 内容都是它的一部分）。
2. 用 `contractLane()` 断言过滤正则回填，而那个夹具里 `filter: null` ——
   我断言的期望值来自**想象**，不是夹具。
3. 想验"清空可选项要真的清掉"，先拿 `filter` 开刀 —— 但 `filter` 是
   `filter` 类型线路的**必填项**（`missing_kind_field`），清空后前端**正确地**
   一条请求都不发，于是断言"调用了一次"红了。**产品是对的，我的用例选错了字段**；
   换成可选的 `exclude_filter` 才是这条规则该测的东西。

第 3 条与 [docs/31] 里 step23 那两次同源：**先证明红在哪一侧，再动手改。**
