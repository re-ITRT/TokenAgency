# 05 · 托盘与界面

目标是 Clash Verge 那种"平时不理它、需要时两下点到"的体验。托盘是**一等公民**，不是网页的后门。

---

## 1. 托盘设计

### 1.1 图标状态（一眼定性）

| 状态 | 图标 | 触发条件 |
|---|---|---|
| 正常 | 绿色圆点 | 全部启用通道可用，无冷却 |
| 降级 | 黄色 | 有通道处于冷却/额度 soft 告警/某 lane 节点故障 |
| 异常 | 红色 | 全部通道失败，或全部 lane 的节点都不可达 |
| 暂停 | 灰色 | 用户手动暂停网关 |
| 实验模式 | 加锁形角标 | 开启了 system_proxy / tun |

图标用 Tauri `TrayIcon::set_icon()` 动态切换；tooltip 随状态刷新：

```
TokenAgency · 策略: 便宜优先 · 出口: 东京-03 (82ms)
今日 1.24M tok · ¥3.42 · 中转A 82%
```

└──────────────────────────────────────────────┘

实现要点（Tauri 2）：

- `TrayIconBuilder::with_menu(...)`，子菜单用 `SubmenuBuilder`。
- 菜单项用 `CheckMenuItem` 表达"当前选中"（策略、节点）。
- 动态内容（额度百分比、延迟数字）在每次 `menu_will_show` / 定时任务中重建菜单文本；Tauri 允许 `MenuItem::set_text()`，避免整菜单重建闪烁。
- 点击行为：左键 = 显示主窗口（`app.get_webview_window("main").show()` + `set_focus()`）；双击托盘图标也显示主窗口。
- 菜单项动作全部通过 `tauri::command` 打到 Rust 侧，UI 与托盘共用同一套命令，**不重复实现逻辑**。

### 1.3 通知策略（克制）

只在下面几件事弹系统通知，其它一律进日志：

| 事件 | 通知 |
|---|---|
| 某个凭据额度耗尽并已自动切换 | "中转站A 额度用尽，已切到 中转站B" |
| 全部通道失败 | "所有通道不可用，请检查网络/订阅" |
| 机场订阅更新失败 | "订阅「机场A」更新失败，仍在用上一次的节点" |
| 所有 lane 的节点都不可达 | "网络不可用，请检查订阅或节点" |

同事件 10 分钟内只弹一次（去重）。

### 2.1 套餐链（⑤ 的默认视图）★ 针对"同模型跨厂商跨网络自动切换"

**这是本页的默认视图，因为它是用户的心智模型。** 见 [03 §0 基准场景](03-routing-and-policy.md)。

```
deepseek-v4.1flash                                    [添加套餐]  [自动排序]
┌──────────────────────────────────────────────────────────────────────────┐
│ ① 字节方舟           直连          ████████░  82%   418/500万   额度/月  │ ← 正在用
│    优先级 10 · 官方 · 标品                                                 │
│    ⠿ 拖拽调整顺序                                                         │
├──────────────────────────────────────────────────────────────────────────┤
│ ② command code       日本线        ██░░░░░░░  21%   ¥4.2/¥20    按量     │
│    优先级 20 · 备用                                                       │
└──────────────────────────────────────────────────────────────────────────┘
   用完自动切下一个 ✓   同会话保持不放 ✓   冷却中/已耗尽自动跳过 ✓
```

每个套餐一行，一眼看清四件事：**走哪条线、还剩多少、排第几、是不是正在用**。
拖拽调整顺序 = 改优先级；点行展开可改线路、上游模型名、标签、额度。

**额度列必须显式**：没配额度的套餐显示灰色 `未设上限` 并带一个 ⚠️ —— 因为
**不填额度就无法"用完自动切"**（[03 §0](03-routing-and-policy.md) 的前提）。这是最容易让人困惑的地方，不能静默。

**线路列直接可改**（下拉），选项就是"直连 / 机场订阅里的组 / 固定节点"——
"每个套餐走哪条线，或者直连"的主入口就在这里。

### 2.2 网络页的「分配」Tab（⑦）—— 批量手动分配

左右两栏：左边是"用它的东西"（模型 / 通道 / 凭据 / 客户端 / 标签），右边是"线路"。支持多选批量改。

外加一个**反向视图**：选中某个订阅 / 分组 / 节点，右侧列出"**哪些通道正在用它**"——删订阅或停节点前先看这里，避免误伤。

### 2.2 策略模拟器（⑥右侧）

常驻面板，输入 → 立即给出命中规则、候选集（含淘汰原因）、最终通道、故障转移链、预计出口节点与延迟。这让"策略"从抽象配置变成可见行为，避免"改了策略结果不知道会发生什么"。

### 2.3 Trace 详情（⑨）—— 出问题时的唯一真源

### 2.4 首次启动向导（3 步，别让人读文档）

```
Step 1  选服务商：勾选你有的（OpenAI / Anthropic / 中转站…）→ 填 key（每个一行，支持粘贴多个）
Step 2  网络：粘贴机场订阅链接（或选"我不用梯子"）
Step 3  验证：自动跑一次连通性测试（每个 key × 每条 lane），给出结果表
        ✅ OpenAI个人 → 日本线 1.2s   ⚠️ 中转A → 日本线 超时（建议改直连）
生成配置 → 显示"复制到 Cursor/Claude Code 的接入信息"（带一键复制按钮）
```

## 3. CLI（可选但推荐，方便脚本与排查）

```
ta serve                          前台运行网关（无 GUI，给服务器/容器）
ta echo <channel>                 发一个带图 + 带特殊头的请求到该通道，回显"上游实际收到了什么"
                                  （用来查"到底是谁吞了图片/吞了 agent 标识"）
ta lane test <lane> [--node X]    测速
ta sub update <id|--all>
ta quota                          打印账本摘要
ta trace <request_id>             打印完整 trace（含 header_diff）
ta simulate --model gpt-4o --image --stream     # 命令行版策略模拟器
ta export | ta import             配置迁移
```

## 4. UI 技术细节

| 项 | 方案 |
|---|---|
| 前端 ↔ Rust | Tauri `invoke` 命令（类型由 `tauri-specta` 生成）；事件用 `emit`。**前端不直连管理 API 8788** |
| 服务端数据 | TanStack Query（Provider/模型/日志分页/成本中心查询）；Zustand 只管 UI 状态 |
| 实时请求流 | Rust 侧 `broadcast::channel` → **环形缓冲 + 200ms 批量 emit** → 前端虚拟列表（保留最近 500 条） |
| 图表 | 主趋势图 **ECharts**（用量按小时聚合，避免渲染 10 万点）；数字卡里的 sparkline **手写 SVG path**，不引库 |
| 表格 | **MUI X DataGrid**（虚拟滚动 + 列固定 + 服务端分页）：请求日志、成本中心、通道矩阵 |
| 主题 | MUI 开 **CSS 主题变量**；`size="small"` + `density="compact"`，表格行高锁 32px |
| 托盘与窗口一致性 | 单一状态源在 Rust（`AppState`），UI 只读不缓存，避免两边显示不一致 |
| 配置变更 | 写 DB → 校验 → 应用 → `emit("config-changed")` → 托盘菜单与 UI 同时刷新（文件监听模式下由文件变更触发） |
| 无障碍/暗色 | 跟随系统；托盘图标需准备 light/dark 两套（Windows 任务栏主题） |
| 单实例 | `tauri-plugin-single-instance`：第二次启动只唤起已有窗口 |
