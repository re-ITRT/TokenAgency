# 15 · 视觉设计系统

> **这一份是界面观感的唯一裁决处。** 冲突时以本文件为准，不以 [07 §1.3] 的具体条款为准（那份讲"看板怎么排"，这份讲"整个产品长什么样"）。
>
> **用户明确要求（第 10 轮）**：
> 1. **不要 emoji**
> 2. **高级、极简**
>
> 这两条不是"偏好"，是**验收标准**。F1–F4 的产物如果不满足，不算完成。

---

# 1. 先说清楚"高级极简"到底指什么（否则会各做各的）

"极简"不是"东西少"，是**每一个视觉元素都必须有理由**。
"高级"不是"用灰色"，是**克制、精确、细节一致**。

具体到可执行的三条：

| 原则 | 具体含义 | 反面（要避免的） |
|---|---|---|
| **克制** | 颜色、边框、阴影、动效**默认都不用**，只在承担信息时才用 | 到处描边、每个卡片都投影、状态用彩色块 |
| **层级靠排版，不靠装饰** | 用字号 / 字重 / 颜色深浅区分主次 | 用彩色标题、大图标、背景色块区分主次 |
| **一致到像素** | 间距只从固定刻度里取；圆角只从两个值里取；同一语义永远同一个颜色 | 随手写 `margin: 13px`、三种不同的圆角 |

**一句判据**：把一个页面截图缩小到看不清文字，**它应该是一张安静的、有秩序的灰度图**。
如果缩小后花花绿绿、到处是框，就不合格。

# 2. emoji：零容忍，但要划清一条边界

## 2.1 硬规则

**我们自己产出的任何用户可见文本里，不许出现 emoji。** 包括但不限于：

- 界面文案：标签、按钮、标题、tooltip、空状态、提示
- **状态表示**（这是最容易犯的）：不许用 `⚠️` `✅` `❌` `🔴` 之类
- toast / 系统通知 / 托盘菜单与 tooltip
- 错误消息、引导页、设置项说明
- `config.example.yaml` 及所有示例配置的注释
- README / CHANGELOG / 安装包文案
- 日志里给人看的消息

**替代手段**（按场景选一个，不要都上）：

| 原来想用 emoji 表达的 | 改用 |
|---|---|
| 警告 / 注意 | 文字（"未设上限"）、或一个 `warning` 色的 6px 圆点、或左侧 2px 色条 |
| 成功 / 完成 | 文字（"已保存"）、或 `success` 色圆点 |
| 失败 / 错误 | 文字 + `danger` 色文字；不要红底白字的大色块 |
| 重点 / 强调 | **字重 500**，不要 `★` |
| 方向 / 趋势 | 数字符号（`+3.2%` / `-1.8%`），颜色只作辅助 |
| 分类 / 标签 | 图标（见 §6）或纯文字 |

## 2.2 ★ 唯一例外：**用户数据原样呈现**

**机场订阅自带的组名与节点名经常包含 emoji** —— 真实样本里就有
`🚀 节点选择`、`♻️ 自动选择`、`🎯 全球直连`、`🇭🇰 香港 01`。

而且 [04 §7.1] 的线路分配机制**必须支持把这类组名直接作为 lane 的出口**，
M0 实测已确认内核接受（K4）。

**所以规则是**：

> **我们永不自己产生 emoji；但凡是来自用户数据（订阅组名、节点名、用户自己填的名称）的字符串，一律原样显示、原样透传，不做任何替换或清洗。**

这条边界必须守住，因为另一侧的诱惑很大（"名字里有 emoji，我给它过滤掉吧"）——
**过滤掉用户的数据是比 emoji 更严重的问题**：会让 UI 显示的名字与内核里的名字对不上，
进而让"线路下拉选中的东西"和"实际生效的东西"不一致。

**实现要求**：emoji 检测只用于**代码审查与守卫测试**（§8），**绝不进入运行时数据路径**。

# 3. 设计令牌（**所有颜色/间距/圆角只能从这里取**）

放在 `src/theme.ts` 导出为 `tokens`，组件里**不许写死颜色字面量**。

## 3.1 中性色阶（深色为基座；浅色是同构映射，不是第二套设计）

刻意**不用**蓝调的"开发者灰"（如 GitHub 的 `#0d1117`），改用**真正中性**的灰阶 ——
这是"高级感"与"工具感"最直接的分界。

| 令牌 | 深色 | 浅色 | 用途 |
|---|---|---|---|
| `bg.base` | `#0B0C0E` | `#FAFAFA` | 窗口底 |
| `bg.subtle` | `#101114` | `#F4F4F5` | 侧边栏、表格斑马行 |
| `bg.surface` | `#141619` | `#FFFFFF` | 卡片、面板 |
| `bg.raised` | `#1A1D21` | `#FFFFFF` | 菜单、弹层、tooltip |
| `border.subtle` | `#1F2227` | `#EFEFF1` | 分隔线（默认用它） |
| `border.default` | `#2A2E35` | `#E1E2E4` | 可交互控件的边界 |
| `border.strong` | `#3A3F47` | `#C9CBCF` | 聚焦前的强调边界（少用） |
| `text.primary` | `#E8EAED` | `#18191B` | 正文与数字 |
| `text.secondary` | `#9BA1A9` | `#63666B` | 说明、单位、次要信息 |
| `text.tertiary` | `#6B7178` | `#8E9196` | 占位符、禁用前的弱化 |
| `text.disabled` | `#4A4F55` | `#B4B7BB` | 禁用 |

**约定**：
- **不用纯黑 `#000` 与纯白 `#FFF`** —— 纯黑在 OLED 上有拖影感，纯白刺眼。用上面的 `bg.base` / `text.primary`。
- 层级优先靠**背景明度台阶**（base → subtle → surface → raised），**不是靠加边框**。

## 3.2 强调色与语义色（**低饱和，不用霓虹**）

| 令牌 | 深色 | 浅色 | 用途 |
|---|---|---|---|
| `accent` | `#5B5BD6` | `#4F4FCF` | 主色：选中、链接、主要按钮 |
| `accent.hover` | `#6E6EE0` | `#4343C4` | 悬停 |
| `accent.subtle` | `#5B5BD6` @ 12% | 同 | 选中行底色、轻量高亮 |
| `success` | `#46B17B` | `#2E8B62` | 仅状态 |
| `warning` | `#D2A24C` | `#9A7420` | 仅状态 |
| `danger` | `#E5605A` | `#C0392F` | 仅状态与破坏性操作 |
| `idle` | `#6B7178` | `#8E9196` | 未知 / 未运行 |

**约定**：
- **强调色只有一个。** 不许出现第二个品牌色。
- **语义色只表达状态，不做装饰**：不要用 `success` 当"好的数字"的颜色去美化 KPI。
- **颜色语义全局唯一**（沿用 [07 §1.3]）：绿=成功 · 黄=需注意 · 红=失败 · 强调色=选中/主操作 · 灰=未知/禁用。**全站不许有第二种含义。**

## 3.3 间距刻度（**只能取这九个数**）

`2 · 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64`（单位 px）

- 控件内边距：`4 / 8`
- 元素之间：`8 / 12`
- 卡片内边距：`16 / 24`
- 区块之间：`24 / 32`
- 页面边距：`32 / 48`
- `2` 只用于表格单元格内的紧凑对齐

**不许出现 `13px`、`18px` 这类刻度外的值。**

## 3.4 圆角（**只有三个值**）

| 令牌 | 值 | 用途 |
|---|---|---|
| `radius.control` | `6px` | 按钮、输入框、下拉、chip |
| `radius.surface` | `10px` | 卡片、面板、表格容器 |
| `radius.overlay` | `14px` | 菜单、模态、tooltip |

## 3.5 层级与阴影（**深色界面尽量不用阴影**）

- **默认零阴影**。层级靠 `bg` 台阶 + `border.subtle`。
- **只有浮层**（菜单、模态、tooltip、toast）用阴影，且只有一个层级：
  `0 8px 24px rgba(0,0,0,.45)`（深色）/ `0 8px 24px rgba(16,17,20,.12)`（浅色）
- **不许**给卡片加阴影来表示"它是个卡片"。

# 4. 排版

## 4.1 字族

```
UI:   -apple-system, "Segoe UI Variable Text", "Segoe UI", "Microsoft YaHei UI", sans-serif
数字: ui-monospace, "Cascadia Mono", "SF Mono", Consolas, monospace
```

- 中文优先 `Microsoft YaHei UI`（`UI` 版本的行高与字重比旧版好）。
- **数字必须等宽**：所有会变化的数字（token 数、金额、延迟、百分比、时间）都用
  `font-variant-numeric: tabular-nums`，**否则刷新时会左右跳动** —— 这是数据密集界面最显廉价的地方。

## 4.2 字号刻度（**只有六个**）

| 令牌 | 值 | 字重 | 用途 |
|---|---|---|---|
| `text.label` | `11px` | 500 | 全大写小标签、表头 |
| `text.meta` | `12px` | 400 | 单位、时间戳、次要说明 |
| `text.body` | `13px` | 400 | 默认正文与表格 |
| `text.section` | `15px` | 500 | 区块标题 |
| `text.page` | `20px` | 500 | 页面标题 |
| `text.hero` | `28px` | 500 | 看板主数字（**一页最多一个**） |

**字重只用 `400` 与 `500`。不许用 `700`** —— 粗体在深色底上会糊。

**行高**：正文 `1.5`；标题 `1.25`；表格与数字 `1.2`（紧凑）。

**字距**：`text.page` 及以上用 `-0.01em`（大字号需要略微收紧）。

## 4.3 数字排版（数据密集界面的成败）

- 千分位分隔；Token 用缩写 `12.4M` / `842K`；**悬停显示精确值**（沿用 [07 §1.3]）。
- **单位用小一号、`text.secondary` 色**，紧跟数字，中间留 `2px`。
- 百分比固定一位小数，**不要 `99.2000001%`**。
- 金额带货币符号，与数字同色同字号（不要让符号变灰，那会让金额看起来不完整）。

# 5. 表格与列表（本项目 70% 的界面）

- 行高 **32px**（沿用既有约定），单元格内边距 `8px` 横向。
- **表头**：`text.label` + `text.secondary`，**下边框一条 `border.subtle`**，无背景色。
- **行分隔**：只用 `border.subtle` 的 1px 下边线；**不用斑马纹**（斑马纹是廉价感的常见来源）；**不用竖线**。
- **选中**：`accent.subtle` 背景 + 左侧 2px `accent` 色条。**不要用彩色整行填充。**
- **悬停**：`bg.subtle`。不做位移、不加阴影。
- **数字列右对齐**，文本列左对齐，状态列居中。
- 状态列**不用彩色 chip**：用一个 6px 圆点 + 文字（`text.body`）。

---

# 6. 图标

- 只用 `@mui/icons-material` 的 **outlined / 线性**变体，`16px`（密集处 `14px`）。
- **默认继承 `currentColor`**，只有语义状态才给色。
- 侧边栏图标 `18px`，与文字间距 `10px`。
- **不许**用 emoji 当图标，**不许**用多色图标，**不许**用填充变体混搭线性变体。
- 图标**永远配文字**（除工具栏按钮），不做"只有图标靠猜"的界面。

---

# 7. 动效

- 时长：`120ms`（状态变化）/ `180ms`（进出场）。**不超过 250ms。**
- 缓动：`cubic-bezier(.2,0,0,1)`（快出缓入）。
- **只用来说明因果**（新行插入、面板展开、值缓动），**不用来炫技**。
- **唯一允许的循环动效**：额度 >90% 时的轻微脉动（沿用 [07 §1.3]），且幅度要小。
- 必须遵守 `prefers-reduced-motion`。

# 8. 机械检查（不靠自觉）

新增守卫测试 `src/app/design.guard.test.ts`：

1. **UI 文案无 emoji**：扫 `src/**`（排除 `mock.ts` 等**模拟用户数据**的文件与 `// ta-allow-emoji` 标记的行），
   命中 §2.1 范围的 emoji 即失败并打印文件:行号。
2. **无硬编码颜色**：扫 `src/**/*.tsx`，禁止 `#` 开头的颜色字面量与 `rgb(`/`hsl(`，
   必须走 `theme.palette` / `tokens`。
3. **无刻度外间距**：扫 `padding|margin|gap` 的数值，必须在 §3.3 的刻度内（`2/4/8/12/16/24/32/48/64`）。
4. **无 `font-weight: 700`**。

> **为什么这些值得做成守卫**：它们都是**静默劣化** —— 多一个 `13px`、多一处 `#333`、
> 多一个 emoji，都不会报错、不影响功能，只会让界面一个月后变得不统一。
> **而"不一致"正是"不高级"的定义。** 这类约定不机械检查就一定守不住。
