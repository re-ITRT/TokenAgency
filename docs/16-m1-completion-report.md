     src-tauri/src/commands/app.rs:152  `info!(gateway = …)`
     src-tauri/src/commands/app.rs:164  `info!(gateway = …)`
   ```
   但 `pr.ps1` 的提交门禁只跑 **rustfmt + clippy（+ 前端 tsc）**，**不跑测试** → 这条 PR 提得出来、也合得进去，
   **一跑全量就红**。处置：去掉结构化字段（这两条是低频人工操作，值没有可检索价值，不值得为它污染白名单），
   把信息放进 message 文本；`log_field_guard` 复跑 **6 passed**。
   **教训与该制度的存在理由完全一致**：`git merge` 不触发 pre-commit，所以"主管的门禁是唯一门禁"——
   而"唯一门禁"必须是**全量**，不是提交门禁。
5. **守卫不封闭：编译期路径 + 共享 `CARGO_TARGET_DIR` 会让"验证"读到错误的树。**
   现象：修复后我在主仓库跑 `log_field_guard` **仍然红**，报的却是**旧**行号（`app.rs:152/164`）。
   根因：这些守卫用 `env!("CARGO_MANIFEST_DIR")`（**编译期**常量）拼路径去读 `src-tauri/**` 源码；
   而 `src-tauri` **不是 ta-core 测试目标的输入**，所以 cargo 认为"目标未变"，**直接复用了在另一个
   worktree（发布快照）里编译出来的二进制** —— 那个二进制里烘焙的路径指向**那个** worktree，于是一个
   早已修好的文件被读成了旧版本。
   - **它不会造成假绿**（读到旧文件只会让它按旧内容判红/绿，但判的是**别的树**），但会让"我在主仓库验证过了"
     这句话**不成立** —— 这正是本项目反复强调的"**证据手法会污染被观察对象**"的第 N 次变体。
   - **本轮处置（诚实记录）**：在发布快照里 **touch 那几个守卫源文件**强制重新编译，让二进制烘焙正确路径后再跑；
     结果 389 + 6 + 3 + 3 + 6 + 3 全绿。
   - **正确修法（登记为后续项）**：守卫改用**运行期**定位（进程 CWD 就是调用 cargo 的那个 worktree 的包根），
     或者给"验证跑"固定一个**专用 `CARGO_TARGET_DIR`**。在那之前，**跨 worktree 复用 target 的验证结论都要标注来源树**。

6. **环境事故（已恢复，但值得记）**：收尾时发现主仓库的 `node_modules` **被清空**（`.bin` 条目数 **0**，
   `typescript` / `vite` / `vitest` 三个包都不在）→ `npm run build` 报 `'tsc' is not recognized`，
   **安装包的前端构建步骤会直接失败**。处置：`npm ci --no-audit --no-fund` 按 `package-lock.json` 重装，
   **added 245 packages** 后恢复（`npm run build` → exit 0）。
   - 顺带发现一个更隐蔽的坑：`tsc` 不在 `.bin` 里时，`npx tsc` **会去网上下一个版本**来跑 ——
     于是"我验证过了"实际上验的是**另一个版本的编译器**。所以门禁里跑前端必须走**项目锁定的**工具链，
     不能用 `npx <tool>` 兜底。

## 5. 结论

**能用的部分**：可安装包已产出（从**干净快照**构建，见 §2）；门禁四项全绿且**无任何 `--exclude`**；
内核看护、网关全透传、路由/粘性/额度判定、可观测性判定层、真实订阅解析（含真实机场样本的脱敏夹具）
都有测试与守卫；**基准场景（A1）已有真 mihomo 的端到端证据，并通过同行评审**；日志页把 C1/C2/C4
补上了用户可见面；暂停/恢复网关修掉了一个"页面上有按钮、点了必然失败"的真 bug；
两条**防漂移守卫**（调用方 ⊆ 注册表 ⊆ 契约）已并入 master。

**不能声称的部分**：`A2` 的真机（Cursor 带图）没跑，只有 wire 级自动化证据；73 条命令仍是"计划面"
（**没有实现**）；事件桥接、参数/凭据/网络三个页面、跨协议适配（G3）、流式计量（G4 第 4 块）未完成；
**契约与 Rust 的日志结构不一致**（日志页用"双写 + 并集读"兜住，用户可见行为是对的，但根上没修，
且**现在没有"形状守卫"**）；四条已知偏离（`accept` 注入、模拟器等价、`kernel.log` 脱敏取舍、
A1 的内核配置是手写等价配置）已在 §3 定名。**§0.1 是这份结论的逐条版。**
