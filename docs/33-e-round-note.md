### 第 124 轮：**E 期的环境结论**（如实降级，不是"没做"）

查清了这个环境的两件事（`scripts/check-kernel-available.py`）：

1. scratch 配置里 `"kernel": { "provider": "external", "path": null }` —— **没有内核可执行文件**；
   PATH 里也没有 `mihomo` / `clash-meta`。也就是说**内核根本起不来**，
   `delay_of()` 无从调用 → "按 `base_url` 测延迟取最低"在这台机器上**无法真机验证**；
2. 就算内核能起：订阅 fixture 给的"节点"是 `127.0.0.1:8388/8389` 这种**假端口**，
   没有任何东西在监听 → 每个节点都会**测不通** → 结论会是 `AllUnreachable`（如实报错），
   而不是"选最低延迟"。要造出"多节点、延迟各不相同"的场景，得先有真的代理端点。

**因此 E 期的证据等级降级为**（按承诺写清，不含糊）：

| 要验的行为 | 证据等级 | 位置 |
| --- | --- | --- |
| 选最低延迟（含"更快的也不换"） | **单测**（不是真机） | `crates/ta-subscription/src/auto.rs`（10 条） |
| 按 **IP**（不是名字）认"同一个出口" | **单测** | 同上（`stickiness_is_by_address_not_by_name`） |
| 全不通 → `AllUnreachable`（不编节点） | **单测** + 真机（真机那次是"内核没起"） | 同上 + 第 123 轮日志 |
| 探测 → 裁决 → 写 `set_select` → 记住地址（**编排**） | **真机只验到"拒绝"那一半** | `apply_auto_export` |
| 端到端（真的按延迟选中并写进内核） | ⬜ **本环境不可验**：需你的机器上装了内核（mihomo）且有可用节点 | — |

**给你的两个选项**（E 期唯一剩下的路）：

* **A：你在自己机器上装/指向内核**（设置页配内核可执行文件），我给你一条**可复现的人工验证步骤**
  （选自动 → 刷新 → 看日志 `「自动」出口已重算 status=…` 与内核 `/proxies` 里那条组选了谁）——
  这条**不需要改代码**；
* **B：给内核控制器抽一个探针接口**，让测试回放延迟表，从而把"探测→裁决→`set_select`→记住"
  整条编排放进 CI。代价 **+1–2 轮**，要动公共接口抽象。

我倾向 **B + A 并行**：B 让这条链路在 CI 里有完整证据，A 让你机器上真的选一次。
