# `docs/` 索引

本目录**只有 16 篇**。这不是省事，是纪律。

## 为什么把"文档编号当接口"这套制度废掉了

它曾经有一条看起来很硬的规则：**编号只增不改，空缺是永久的**；还配了一页账目记录每个空缺。
但真实情况是：

* 全仓有 **2500+ 处** `docs/NN` 引用（`docs/28` 一份就背着 291 处），**没有任何编译器或测试在检查它们**，
  所以失效是**静默的**；
* 代码引用 `docs/24`，而那一篇**从未入库**（旧索引记着这件事：主题是"多窗口额度"，功能已在第 314 轮删除）；
* 更糟的一类不是悬空引用，而是**指到了一个真实存在、却不含所声称内容的文件**：
  两处文档都写着"MIT 全文已登记在 `THIRD_PARTY_NOTICES.md`"，而那个文件里**从来没有过那段全文**。
  这一条**没有任何账目记录**，是这次清理时才发现的。

结论：**一套靠人维护的引用制度，最终会变成"看起来有处可查、点进去是 404"**。
所以不再维护它 —— 约束写进代码注释里，**自足到不需要翻文档**。

## 现在的规则（由 `src/app/docsRef.guard.test.ts` 机械保证）

1. `docs/` 的篇数**只许减少**（棘轮，当前 16）；
2. `docs/` **之外**不许出现 `docs/NN` 形式的引用；
3. 文档之间互相引用编号是允许的（这份索引就是靠编号导航）。

要新增一篇，先想清楚**它凭什么配得上一个编号**。

## 被删掉的 35 篇去哪了

删掉的是**逐轮过程文档**（"第 N 轮需求 / 落地记录"，最长的那篇 4065 行）。
它们的结论没有丢，走了两条路：

1. **落进代码与守卫** —— 这个仓库的规矩是：踩到"静默失效"型缺陷就**补一条会红的守卫**，
   而不是只写进文档；
2. **关键决策以「决策记录」形态并入** [02](02-config-and-data-model.md)、
   [07](07-ui-pages-and-cost.md)、[50](50-plugin-and-capability-minimization.md)。

过程本身留在 git 历史里：

```powershell
git log --diff-filter=D --oneline -- docs/            # 哪些提交删了文档
git show <sha>:docs/28-lines-belong-to-providers.md   # 看被删的那一版
```
