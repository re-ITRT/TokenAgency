用户原话（2026-10-13）：

> 优化全部的界面，文字内容太多了，你每一个页面都截图验证，哪些是没必要的形式，
> UI 可以怎么优化我想做一个完美主义，极简主义的软件。

两条裁决：

1. **契约出处（`docRef`）彻底删除** —— 连 `routes.ts` 的字段与守卫测试一起删；
2. **激进极简** —— 界面几乎只剩「状态 + 操作」；解释进 `?` 气泡；表格 ≤6 列；空态 1 行。

## 1. 诊断：界面在**解释自己**，而不是**显示状态**

这不是印象，是量化结果。改造前的基线（`docs/60` 立档时实测）：

| 指标 | 改造前 |
| --- | --- |
| 中文文案总数 | 981 条 |
| **超过 36 字的长句** | **101 条（10%）**，其中**版面可见 88 条** |
| 按页面分布 | network 25、providers 22、settings 16、cost 14、logs 10、models 9 |

| `?` 气泡 | 21 处 |

### 七类噪音（每类都在真机截图里指到了具体位置）

1. **开发向溯源**：每页标题下的 `契约出处：…`；
2. **实现细节泄漏**：`调 app_set_autostart（注册或移除系统启动项）`（函数名）、
   `注册机制：windows-run-key`、`等后端命令落地后再补`（**把 TODO 印在界面上**）、
   `（本地筛选，不是后端检索）`；
3. **自我辩解式标题**：`数据口径（先说清哪些是估算）`、整张卡片只为说 `只展示，不改系统网络` + 4 个否定句；
4. **冗余回显**：`当前条件：时间范围=今天·分组维度=模型·指标=…` —— 紧贴三个下拉框再念一遍；
5. **表格过宽**：网络页订阅表 **14 列**，表头被挤成**逐字竖排**（`自动识别`→`自 动 识 别`），
   `最近更新时间：2026-10-07 06:31:51` 把整行撑到 **6 行**高；
6. **成句解释占版面**：`按需勾选。勾上的端点才会被网关接受；没勾的会当场报错并指出是哪个开关（不会被转发到上游）。`；
7. **旁白式状态**：`对比上期：不可得（后端返回里没有上期字段，所以不给涨跌）`。

## 2. 五条规则（每条都有可执行检查）

| # | 规则 | 判据 |
| --- | --- | --- |
| 1 | **不解释实现** | 文案/ tooltip 都不得含函数名（`app_*`/`config_*`…）、`后端`/`前端`、`本地口径`/`远端`/`本地筛选`、`字段`/`枚举`、`接线`/`落地`/`在途`/`还没实现`、文档编号 `§`、`契约`、`TODO`/`待补` |
| 2 | **句子级说明进 tooltip** | **版面上**的文案 ≤36 字；更长的必须进 `?` 或详情抽屉 |
| 3 | **一屏一个主操作** | 副操作收进溢出菜单或降级为 text；**没有多选场景就不出现勾选框** |
| 4 | **表格默认 ≤6 列且不换行** | 列头不得竖排；长内容换短格式或进详情 |
| 5 | **空态只说"怎么开始"** | 1 行 + 1 个按钮；不解释数据来源 |

**关键设计**：规则 2 必须区分"版面"与"tooltip"。`docs/22` 早就把页头说明收进问号圆圈了 ——
那是**对的**（按需展开不是噪音）。第一版守卫没做这个区分，把 100 条全算违规，
其中 21 条本来就是 tooltip 文案 —— **守卫自己制造了 21 个假阳性**。

## 3. 机械守卫：`src/app/uiMinimalism.guard.test.ts`

守卫五条规则里的三条（规则 3/4/5 需要看结构，另有逐页断言与 e2e 截图）：

| 检查 | 类型 |
| --- | --- |
| 规则 1：zh + en 文案里没有实现向词汇 | **硬性 0** |
| 规则 1b：源码**字符串字面量**里没有 `§`；`docRef` 已彻底删除 | **硬性 0** |
| 规则 2：版面文案 ≤36 字 | **棘轮**（88 → 33） |
| 规则 2b：没有无人引用的死文案 | **棘轮**（240 → 214） |
| **守卫自检**：合成样本里"字符串的 `§` 必须抓到、注释的必须放过" | 两端都钉住 |

### 3.1 棘轮（ratchet）纪律

规则 2 与 2b 是**只许变小**的上限。收紧时改 `LIMITS` 里的数字，**不许调大**。

### 3.2 守卫自检：为什么必须有

守卫最容易的坏法是**永远绿** —— 正则写错、路径没扫到、提取器把内容全滤掉，
它都会变成一块安慰牌。所以有一条用例喂它两个合成样本：一个**必须报警**、一个**必须放过**。
它红了说明守卫坏了，而不是产品坏了。

### 3.3 规则 1b 的三次假阳性（守卫自己犯的错，都留在了注释里）

1. **按"行"判断是不是注释** → JSX 注释 `{/* … */}` 与块注释的**续行**都不以 `*` 开头，
   于是 4 条纯注释被报成违规。改成"先把块注释挖掉，再取引号里的内容"；
2. **用正则全量搜引号** → 英文文案里的撇号（`don't`）被当成单引号串的开头，
   一路吞到几十行之外的注释才闭合。改成**从左到右一次扫描、整体消费每个字面量**；
3. **把 `*/` 写进块注释**里 → 直接把注释提前终止，守卫文件自己编译不过。

### 6.1 一个必须记下的"覆盖率回退"

改造后第一次 e2e 出现 `PASS=29 SKIP=3`：`step13`（订阅流量）从 PASS 退化成 SKIP。

### 8.1 新判据 A：**空态不复述页面上已有的动作**

用户要的是"少"，不是"空态必须凑一个按钮"。所以判据是：
**同屏已经有同标签同动作的控件时，空态只留 1 行说明。**
反过来，空态**独有**的入口要保留（例如 `/network` 线路空态的「去服务商页」）。

### 8.2 新判据 B：**行内写控件不许把行撑成两行**

任何单元格里的控件都不得让该行换成两行；一行只留一个主操作或一个 `⋮`。
`ui-network2` 把它做成了**可机械检查**的形式（每行操作格里 `button/input/[role=menuitem]` 合计恰好 1 个）。

### 8.3 删掉线路批量选择（一个需要交代的取舍）

线路**不是用户维护的清单**（[docs/58](58-lanes-come-from-providers.md) 已删掉手动建线路的界面，
线路由后端在服务商页选「网络代理」时按需建出），一屏通常 1–3 条，而行内 `⋮` 里已经有「删除」。
要用户先学"勾选 → 一次确认 → 逐条调用"只为了删两条，是**形式大于功能**。
订阅表的批量**保留** —— 订阅确实由用户自己维护。

### 8.4 这一轮最该记住的一课：**判据错了，删的就是活代码**

第 2 轮我给三个 teammate 派了"删死文案"的任务，判据是"全仓没有 `t("key")` 引用"。
实测**全仓 191 条"孤儿"**。但正确判据下**真死键只有 7 条** —— **假阳性率 96%**。

原因：本仓大量使用**"键名先存进对象/常量，之后再传给 `t()`"**的写法：

```rust
// KernelStateDot.tsx：状态 -> 键名的映射对象
stopped: "status.kernel.stopped",
// providers/editor.ts：键名存进数据字段
issues.push({ field: "baseUrl", message: "wizard.invalidUrl" });
// providers/index.tsx：类型化的常量
const SELECT_ALL_LABEL_KEY: I18nKey = "common.selectAll";
```

照错清单删，`status.kernel.*`、`wizard.invalidUrl` 这些**正在用的**文案会被删掉。
我在 teammate 动手**之前**发现并群发更正，三份映射里的 `delete` 都是 0–4 条（无人受损）。

正确判据（守卫里已固化为注释与实现）：

> 一个键**只要它的字符串本身**出现在 `src/**` 里（`shared/i18n/` 除外，**含测试与注释**），就算被引用；
> 再加 `` t(`prefix.${x}`) `` 动态模板前缀的覆盖。取向是**保守** ——
> 宁可少报死键（留一条没用的文案），也**不可多报**（删掉在用的文案）。

## 9. 第 3 轮：一个**我自己造成的**严重问题 —— 映射应用顺序

第 2 轮我报告"版面 >36 字：32 → 8"。**那个数字是错的**（它虚高），而且成因是我的工具，
不是内容 —— 这一轮把它查清了。

### 9.1 现象

第 3 轮复查时发现 `providers.connection.hint` **仍是 56 字的旧句**，
而 teammate 的报告明确说"已压到 15 字"。查它的映射文件：**值确实写着 15 字**。
再跑一次应用器，输出是 `set 7 条`——**报成功，文件也确实被改了，但值没变**。

### 9.2 根因：`sorted()` 在 Windows 上把第 2 轮排到了第 1 轮**前面**

应用器要按"轮次"应用映射（第 1 轮先、第 2 轮后，后来的覆盖先前的）。我原来写的是：

```python
files = sorted(glob.glob(".ta-tmp/ui-*/i18n.json")) + ...
```

glob 在 Windows 返回**反斜杠**路径。比较 `.ta-tmp\ui-providers2\i18n.json` 与
`.ta-tmp\ui-providers\i18n.json` 时，在 `ui-providers` 之后比的是：

* `2`（0x32）
* `\`（0x5C）

**`2` 比 `\` 小** ⇒ `ui-providers2` 排在**前面** ⇒ 第 1 轮的旧文案**覆盖**第 2 轮的新文案。
`network2` / `record2` 同理。于是"第 2 轮的结果"从来没真正生效过。

修法：**显式按轮次排序**（`ui-x` 是第 1 轮，`ui-x2` 是第 2 轮，`ui-lead` 永远最后）：

```python
def order(path):
    d = os.path.basename(os.path.dirname(path))
    m = re.match(r"^(.*?)(\d+)$", d)
    base, rnd = (m.group(1), int(m.group(2))) if m else (d, 0)
    return (1 if d == "ui-lead" else 0, base, rnd)
```

### 9.4 这一课比上一个更值钱
