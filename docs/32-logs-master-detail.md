## 2. 两个**数据缺口**（这是本轮最该先说清的成本）

① **计数**（左边三个筛选片 + 分页总数）：现有接口只给"符合条件的若干行"，
   没有"成功/失败各多少条、总共多少条"。要做成截图那样，必须有一个**聚合查询**
   （`GROUP BY status` + `COUNT`），否则前端只能靠"拉全量再数"——那是假分页，会拖死大表。

② **四张统计卡**：同上，需要一次 `COUNT` + `AVG(latency)`（可以并进①的同一个查询）。

**这两条是后端 + 契约 + bindings 的整块活**（不是纯前端排版），所以这条重构比"清文案"重得多。

## 4. 纪律（照旧，先写下来免得走样）

* **不编数字**：计数与统计卡只显示后端聚合出来的值；拿不到就说"读不到"，不填 0；
* **不假分页**：没有总数接口之前**不做**"1 / 2009"这种页码（那是骗人）；
* **不删真功能**：存储/模式/保留/导出是这个应用的真能力，收进折叠区，不许为了像截图而删；
* **不造 emoji**、不硬编码颜色（既有守卫会拦）；
* 每片都要：单测 + （后端片）真机 + 更新 `docs/31` 的进度与 ETA。

### 测试当场抓到的两个真问题（都值得记）

1. **`trace` 表没有 `outcome` 列**：它是读时按 `status` / `error` / **尝试次数**推导的。

   现在抽成常量 `OK_CONDITION` 与 `map_trace_row` **同口径**

2. **测试隔离**：三个测试原本共用"临时目录 + 进程号"，同一进程里互相看到对方插入的行
   （被 `empty_result_is_none_not_zero` 抓住）→ 改成 `open_memory()`（每个测试一个内存库）。

## 7. L2 收尾（第 132 轮：三个计数筛选片已完成）

三个片（全部 / 成功 / 失败）**数字与统计卡同源**（同一个 `log_stats`），点片即筛。

**一个必须写死的口径**：`失败` 片 = **`failed` + `retried`**。
