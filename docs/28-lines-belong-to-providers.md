## 1. 三个实体，职责重划

| 实体 | 在哪创建 / 编辑 | 里面有什么 |
| --- | --- | --- |
| **服务商** | 服务商页（向导 = 同一件事的首次创建） | **基础数据**：显示名、`base_url`、**唯一一把密钥**、协议、默认网络代理（线路） |
| **线路**（原来叫通道） | **服务商详情页**："编辑线路" | 一个上游模型（名字 + 扫描记录下来的模型信息）、**网络代理**、启用与否、权重/优先级 |
| **模型** | **模型页**：**分配**线路 | 对外暴露的逻辑名、别名、**它要用哪几条线路**（≥1）、公开的模型信息（能力/上下文，来自所分配线路记录的上游信息） |

**由此产生的三条硬规则**：

1. **创建服务商与线路 → 不自动创建模型**（原话："模型是不自动创建的，是等待用户去分配的"）。
   模型只会因为用户在模型页分配了线路而出现。
2. **没有"为模型选网络代理"这回事** —— 向导里没有、服务商页里也没有。代理是**线路**的属性，
   只在"编辑线路"里改（[docs/21 §4.3] 那条"线路只读"的旧约束随之作废：现在代理的编辑口就在线路自己身上，
   但**不是**在模型上）。
3. **一个服务商一把密钥**：`credential` 退化成服务商的 1:1 附件（页面不再有凭据表、不再有批量删除）。
   要多个账号 → **加多个服务商、取不同名字**（原话）。

## 2. 关系：由模型侧持有的多对多

* `Model.lines: Vec<ChannelId>`（**唯一真源**）；`ChannelConfig.model` **删除**。
* 一条线路可以服务多个模型（"一个线路可以给多个模型提供"）；一个模型由多条线路构成。
* 校验器：
  * 每个 `model.lines[i]` 必须指向存在的线路（悬空 = 硬错误）；
  * **一个模型至少要有一条线路**（原话："添加模型至少选一个线路"）—— 否则它对外可调用却必然失败；
  * 客户端请求的模型名 → 解析到**模型**（id 或别名）→ 取它的 `lines` → 再走策略/权重/粘性。
    **别名不再落在"线路"上**（线路没有名字了）。
* 删除方向（[docs/27 §1.2] 不变）：删模型**不动线路**；删线路 → 从所有模型的 `lines` 里摘掉 →
  **摘完一条都不剩的模型自动删除**（现在真的是这件事，不用再靠"拒绝删除"来表达）。

## 3. 模型信息与能力（[docs/27 §1.4] 的落地）

* 线路的模型信息 = **扫描时把上游那一条模型对象原样记下来**（能读到的字段逐字存，读不到的就没有）。
* 模型对外公开的信息 = 它在模型页定义的那份，字段**只能来自**它所分配线路记录到的上游信息。
* 兼容判据**单向**（用户给的反例）：`模型声明 ⊆ 每条线路`；线路更强允许，反过来报
  `TA-2007` 并逐字段列出"哪条线路缺了什么"。
* 上游没给的字段**一个都不编**；模型详情里如实写"上游未提供"。

| 期 | 内容 | 状态 |

## 5. S1 的验收

1. **老库能开**：迁移把每条 `channels[].model` 变成对应 `models[].lines` 的一条；迁移**幂等**
   （再开一次不重复加）；迁移后配置仍然校验通过。
2. **路由等价**：同一份配置在迁移前后，`routing::simulate` 对同一请求给出**同一条通道**
   （这是"翻转没有改变行为"的唯一硬证据 —— 逐条对拍）。
3. **多对多成立**：一条线路同时被两个模型引用时，两个模型都能路由到它；从其中一个模型摘掉不影响另一个。
4. **校验器**：悬空 `lines` 报错；模型 0 条线路报错；错误信息点名具体 id。
5. **内核生成**：生成结果里每个模型对应的代理组仍由它的线路构成（与翻转前等价，快照测试钉住）。
6. 门禁：`cargo fmt --check` / `clippy -D warnings` / `cargo test --workspace` / `npm test` / `tsc` /
   `scripts/build.ps1` 全绿。

### 第 81 轮：网络代理下拉的来源（用户现场 + 向导里选代理）

用户原话：
> 「我在网络那边添加了订阅也加载出来了，但是在服务商那边依然无法对一个线路切换网络，
> 另外，在向导添加的时候，我希望也是可以选择代理网络的」

**现场查清（只读他的真实库，未改一个字节）**：他的 `config.lane` **一条都没有**（`doc.lanes` 为空），
订阅表里那条订阅 `url` 是空的、`node_count=0`、`subscription_version` 零行，且

一条线路都没有时它只剩「不指定（继承）」——不是下拉坏了，是**没有可选项**。

按用户当场选定的方案落地（他两个问题各选了一个答案）：

| 需求 | 决定 | 落地 |

**不编数据的边界**（这几条都有测试钉）：

* 节点名不在已采纳版本里 → 报错**点名**并给出可见示例，库里一条都不多建；

  线路占用 → 报错点名，**绝不覆盖**用户已有的配置；
* 生产写入走与手工新建**同一条**路径（`upsert_lane`：校验 → 事务 → 快照 → 内核重载）。

新增覆盖：Rust 3 条（列出来源 / 建了再复用 / 拒绝不存在与 id 冲突）、前端 2 条
（服务商页"选节点 → ensure → 写 channel.lane 且其余字段逐字保留"、向导"第 1 步有下拉 + 第 2 步逐条
选节点 → ensure → 整条覆盖写"）、真机 E2E 新增 `step25`。

### 第 81 轮补：**「直连」必须单独列出来、永远排第一**

用户追问：
> 「网络代理选项中最重要的是直连，这个你都没单独列出来？」

这是**真问题**（两点都成立）：

1. 渠道页第一项写的是「直连（继承）」，而我在服务商页 / 向导里用的是
   `channels.lane.inherited`（"继承（凭据 / 服务商 / 默认线路）"）—— **一个"直连"都没提**；
2. 配置里没有 direct 线路时（正是用户的现场），后端过去只列已配置线路 → 整个下拉里
   **根本没有"直连"这一项**。

修法（顺序是有意的）：

| 位置 | 内容 |
| --- | --- |
| 第 1 项 | **直连**：已配置的 direct 线路 → 用它自己那条（`kind: direct` + `lane_id`）；配置里没有 → 后端仍给一项 `direct:` 标记，选中由新命令 `lane_ensure_direct` 把 `direct` / 「直连（本机网络）」建出来（幂等，已有则复用；id 被别的线路占着 → 报错点名、绝不覆盖） |
| 第 2 项 | **继承**（`""` → `lane: null`）：跟着凭据 / 服务商 / 默认线路走，末端才是直连 |
| 之后 | 其它已配置线路、订阅节点 |

**为什么"直连"与"继承"必须并存**：直连是**钉死在本机网络**上（以后别人把服务商/默认线路改成代理，
这条线路不会跟着变）；继承是**跟着上层走**。两者在界面上是两项、在库里是两个不同的值
（`lane: "direct"` vs `lane: null`）。

**真机 E2E 实测（`step25` PASS，证据逐字）**：


### 第 82 轮：**一个列表 + 滑块**（扫描即全部建出、默认关闭、全选）

**改法**（向导与详情页**共用同一个 `LinesSection`** —— 两处一旦各画一套，行为迟早分叉，

| 之前 | 现在 |
| --- | --- |
| 扫描 → 勾选框选线路 → "创建选中的线路" | **扫描 = 记录目录 + 把目录里每条线路都建出来**（`provider_lines_create_all`，**默认关闭**） |

| 没有批量开关 | 列表头 **全选**（`channel_bulk_set_enabled`：一条命令、一次写库、一次内核重载） |

要点与边界（都有测试钉）：

* `provider_lines_create_all` 幂等：已有线路的条目**一个字节都不动**（不覆盖用户改过的
  `lane` / `enabled` / 优先级）；一条都没补时**不写库**（`created: 0`）；目录空 → 报错点名"先扫描一次"；
  没有启用中的凭据 → 一条都不建。仍然**不建模型**（[docs/28 §1] 硬规则 1）。
* **默认关闭**是命令写入的（`channel.enabled = false`），不是界面假象。
* 批量命令的取舍：全选是**一次用户动作**；前端循环发 N 条 `channel_set_enabled` 会让
  "改了 200 条"变成 200 个配置快照 + 200 次内核重载，中途失败还会留下半开半关的状态。
* 向导里**没有删除入口**（新增流程不删东西）→ `onRemove` 不传就不画那个按钮（假按钮比没按钮更糟）；
  详情页保留「移除线路」（删除与**停用**是两件事：停用的行还在列表里、还能设代理）。

**真机 E2E（`step2` / `step24` / `step25` 实测）**：

同轮修掉的两处**证据读取**缺陷（都不是产品缺陷，但不修就会一直误报）：
① `dumpScratchDb` 从来没 dump `provider_model_catalog` → step24 永远读到"目录 0 行"；

| 之前（每条线路都重复一遍） | 现在 |
| --- | --- |
| 每行上方一个「网络代理」标签 | **列头说一次**：名称 · 网络代理 · 全选 · `3/4` |
| 每行开关右边写「启用」/「关闭」两个字 | **只留开关本身**（符号即语义，`aria-label` 照旧） |

### 事故留档（必须记住的一次）

补 i18n 键时我用了一条**错误的正则**（模式里有空分支 `|)`，于是它在每个字符位置都匹配），
